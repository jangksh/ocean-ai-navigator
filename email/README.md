# 이메일 구독 시스템 (A 구독폼 + B 주간 팁 + C 5일 미니 강의)

결과 화면에서 이메일을 받아 → 확인 메일(더블 옵트인) → 5일 동안 하루 한 통 → 이후 10주 동안 매주 한 통(유형별 팁)을 보낸다.
외부 이메일 서비스 없이 **Google 스프레드시트 + Apps Script**로 무료 운영한다.

| 파일 | 역할 |
|---|---|
| `../index.html` | 결과 화면의 구독 카드, 전송, GA 이벤트 |
| `../subscribe_config.js` | `endpoint`(Apps Script 웹앱 URL). **비어 있으면 카드가 숨겨진다** |
| `copy.js` | 원고 원본: 5일 강의, 유형 성향별 주간 팁, 맹점 문구 (영/한) |
| `build_content.js` → `content.json` | 원고 + 32유형 데이터를 합친 생성물. 사이트에 배포되고 발송기가 가져다 쓴다 |
| `apps_script/Code.gs` | 구독 접수·확인·발송·구독취소 (Google Apps Script에 붙여넣기) |
| `test_engine.js` | 발송 로직 검증 (`node email/test_engine.js`) |
| `../privacy/index.html` | 개인정보 안내 (영/한) |

## 발송 구성

- **강의 5통**: 환영(내 유형 요약·추천 AI) → AI 맞춤 설정 → 반복 업무 템플릿 → 내 유형이 놓치기 쉬운 것(5개 성향별) → 주간 루틴 + 답장 유도("team"이라고 답장하면 팀 기능 수요 확인)
- **주간 팁 10통**: 유형 코드의 5비트(O,C,E,A,N)마다 높음/낮음 각 2개 팁이 있고, 주차마다 차원을 돌려가며(1주 O → 2주 C → … 5주 N → 6주 O 두 번째 팁) 고른다. 32유형 모두 10주간 중복 없이 받는다.
- 영어가 기본, 한국어로 신청하면 한국어. 한국어는 유형 공감 리포트(`insight`)가 없어 그 문단이 빠진다.
- 간격: 강의는 20시간 이상, 팁은 6.5일 이상. 발송기는 매일 오전 9시(스크립트 시간대)에 한 번 돈다.

## 설정 (약 20분, 직접 하셔야 하는 부분)

계정·권한 승인이 필요해서 Claude가 대신할 수 없다.

1. Google 스프레드시트를 새로 만든다 (이름 예: `AI-OCEAN subscribers`). **공유하지 않는다** (이메일 주소가 들어간다).
2. 확장 프로그램 → Apps Script → `apps_script/Code.gs` 내용을 통째로 붙여넣는다.
3. 맨 위 `CONFIG`에서 `POSTAL_ADDRESS`를 채운다. 미국 CAN-SPAM은 모든 상업성 메일에 실제 우편 주소를 요구한다. **집 주소 대신 사서함(PO Box)이나 사업장 주소를 권한다.** 비어 있으면 발송 자체를 막아 둔다. 필요하면 `REPLY_TO`도 채운다.
4. 배포 → 새 배포 → 유형 "웹 앱" → 실행 사용자 "나", 액세스 권한 "모든 사용자" → 배포. 권한 승인 창이 뜨면 스프레드시트, 메일 발송, 외부 요청 권한을 허용한다. 나온 `…/exec` 주소를 복사한다.
5. 편집기에서 `setupTrigger`를 한 번 실행한다 (매일 발송 트리거 등록).
6. `previewToMe`를 실행하면 내 메일함으로 샘플 16통(영 8통, 한 8통)이 온다. 디자인·문구를 눈으로 확인한다.
7. 복사한 주소를 `subscribe_config.js`의 `endpoint`에 넣고 배포한다 (Claude에게 주소를 알려 주면 PR로 반영한다).
8. 사이트에서 본인 이메일로 실제 신청해 본다: 확인 메일 → 링크 클릭 → 1일차 메일 도착 → 하단 구독 취소 링크가 동작하는지 확인.
9. (선택) GA4에서 `subscribe_submit`을 핵심 이벤트로 표시한다.

배포 전 미리 보기: 사이트 주소 뒤에 `?subscribe_preview=1`을 붙이면 `endpoint`가 없어도 카드가 보인다 (전송은 하지 않는다).

## 규모 한도 (중요)

Google 공식 문서 기준 Apps Script 일일 메일 수신자 한도는 **일반 Gmail 100통, Workspace 1,500통**이다 (한도는 예고 없이 바뀔 수 있다).
출처: [Apps Script Quotas](https://developers.google.com/apps-script/guides/services/quotas)

한 명이 평생 받는 메일은 확인 1 + 강의 5 + 팁 10 = 최대 16통이다. 신청자 중 확인하는 비율을 60%로 가정하면(추정) 신청 1건당 평균 약 10통이므로, **일반 Gmail 계정은 하루 신규 신청이 약 10건 이하**일 때 장기적으로 안전하다. 이를 넘기면 MailerLite·Buttondown 등으로 옮기는 것이 맞다. 스크립트는 한도가 20통 미만으로 떨어지면 신규 신청을 보류해 기존 구독자 발송을 우선한다.
시트의 `subscribers` 탭을 CSV로 내보내면 다른 서비스로 이전할 수 있다.

## 원고 수정

1. `email/copy.js` 수정 → `node email/build_content.js` → `node email/test_engine.js` → 커밋·배포
2. 발송기는 배포된 `content.json`을 최대 30분 캐시로 읽는다. 스크립트를 다시 배포할 필요 없다.
3. `content.json`은 사이트에 공개된다. 유료 콘텐츠를 여기에 넣지 않는다.

## 알려둘 한계

- 발신은 설정한 Gmail 주소다. 도메인 인증(SPF/DKIM)을 직접 통제할 수 없고 `List-Unsubscribe` 헤더를 달 수 없어, 스팸함으로 갈 가능성이 전문 서비스보다 높다. 첫 100통 정도는 받은편지함 도달 여부를 직접 확인한다.
- 폼은 `no-cors`로 전송하므로 브라우저가 서버 응답을 읽지 못한다. "확인 메일을 보냈습니다" 문구는 전송 요청이 나갔다는 뜻이고, 도착은 확인 링크 클릭 수(시트의 `confirmed_at`)로 본다.
- 유럽 방문자를 받는다면 GDPR상 동의 방식(체크박스 등)을 별도로 검토해야 한다. 현재는 더블 옵트인과 명확한 고지로 설계했다. **법률 사항은 전문가 확인 필요.**
- 개인정보 안내(`privacy/`)는 이 구조(Google 시트·Google 메일)를 기준으로 쓴 초안이다. 서비스를 바꾸면 함께 고친다.

## 중단·보완 기준 (제안, 조정 가능)

- 결과 화면 노출 대비 신청(`subscribe_submit`/`subscribe_view`)이 300회 노출에 15건(5%) 미만 → 문구·위치를 바꿔 한 번 더 시도.
- 확인률(신청 대비 `confirmed_at`)이 40% 미만 → 확인 메일 제목·스팸함 도달 점검.
- 1일차 이후 구독 취소 비율이 높거나 주간 팁 열람이 급감 → 원고 재설계 (열람률은 이 구조에서 측정되지 않으므로, 필요하면 전문 이메일 서비스로 이전).
